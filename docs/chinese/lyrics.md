# 歌词指南

[English](../lyrics.md) · [文档索引](../README.md)

## 使用与设置

在「设置 → 辅助功能」调整：

| 设置                 | 默认 | 说明                                                     |
| -------------------- | ---- | -------------------------------------------------------- |
| 显示歌词             | 开   | 播放页同步歌词，同时控制 Android MediaSession 歌词副标题 |
| 联网搜索歌词         | 开   | 缺少歌词时联网搜索；关闭后仍可使用已有缓存               |
| 歌词搜索自动重试次数 | 2 次 | 范围 0～10，不含首次搜索；0 为关闭自动重试               |
| 歌词缓存管理         | —    | 查看正文、删除单首或清空全部                             |

当前行随实际播放进度高亮，支持拖动进度后重新定位。自动滚动将当前行居中；手动浏览停止操作 3 秒后恢复跟随。系统开启减少动态效果时不使用平滑滚动。

优先使用歌曲已有 LRC，再使用本地缓存；需要联网时，每轮先尝试公共 Meting（网易云），再尝试 LRCLIB。失败或没有匹配结果时按设置重试，间隔依次为 1、2、4 秒，之后最多 5 秒。切歌或关闭歌词会取消旧任务；Android 离开播放页后，原生播放所需的加载可继续进行。

## 缓存管理

进入「设置 → 辅助功能 → 歌词缓存管理」：

- 「查看 / 收起」展开或关闭缓存 LRC 正文。
- 「删除」只移除选中记录，「清空全部」移除所有记录；两者均需确认。
- 删除不会移除音频文件，也不打断当前已加载的歌词；下次加载可以重新获取。
- 删除过程中尚未完成的旧请求不会把缓存重新写回。
- 页面支持刷新，兼容历史网页缓存；每个活动缓存最多保存 100 条成功结果，不缓存失败结果。

网页端使用 localStorage，Android 使用独立的原生缓存，便于后台播放访问。原生缓存不包含在 localStorage 数据导出中。

缓存去重使用 NFKC 规范化后的歌名和歌手，忽略大小写及连续空白；专辑和来源仅作为元数据。已知时长在 5 秒内且只有一个候选时复用，精确时长优先；未知时长仅匹配未知时长，Live 等版本标记保留。缓存时长锚点固定，避免连续小幅变化误合并不同版本。管理页显示时长以便区分。

旧缓存自动迁移为 v3，优先保留时间戳较新的记录。Android 管理页先将网页缓存导入原生缓存，成功后才移除网页副本；导入失败保留原始数据，时间戳相同时保留原生记录。

## 更换公共服务

将仓库根目录 `.env.example` 复制为 `.env.local`，修改 `VITE_METING_API_URL`，重启开发服务器或重新构建 Android。该值会进入客户端构建，不能用于保存密钥。

服务必须支持 Meting 搜索协议，返回歌曲名、歌手和同源 HTTPS 歌词地址；网页调用还需支持跨域。公共节点可用性可能变化，失败时会回退 LRCLIB。联网搜索会把歌名与歌手发送给服务。

匹配使用规范化歌名及歌手别名；有时长时校验 5 秒以内的差异。标准 Meting 结果常不提供时长。支持行级 LRC 的毫秒、小数时间戳、多时间戳及 offset；不做简繁转换，也不提供逐字高亮。

## 锁屏和通知栏

Android 原生层负责加载、重试、缓存和计时，前台页面共用同一仓库。歌名保持不变，当前歌词替换歌手副标题；没有歌词、尚未开始或当前为空行时显示歌手。只有歌词变化时刷新元数据，不修改曲库内的歌手信息。

媒体播放前台服务及播放期间的唤醒支持用于熄屏同步。各系统对锁屏元数据的展示可能不同，仍需真机验证。原生修改后须执行 `npm run android:build`，再通过 Android Studio 编译安装；仅刷新网页不会更新 Java 代码。

## 开发与排查

[英文指南](../lyrics.md#implementation-and-checks)列出了实现文件与验证命令。

- 找不到歌词：检查歌名、歌手标签、联网开关与网络连接。
- 歌词匹配错误：删除该缓存后重新搜索，必要时修正歌曲标签。
- 缓存内容为繁体：显示的是来源原文，界面语言不会转换歌词。
- 锁屏仍显示歌手：确认开关已开启、有可用同步歌词，并检查安装版本及系统展示行为。
- 缓存操作失败：点击刷新后重试。
